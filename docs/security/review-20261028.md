# Runtime finding review — 2026-10-28

Status: **no production clearance**. The scanned images retain nine unique HIGH
OS CVE identifiers in speech and eight in chat; the native llama image has none
at that severity in this snapshot. Package-level counts are larger because
several binary packages share a source. No listed stable-package fix was present
in the recorded scan. Scanner severity, vendor urgency and API reachability are
different assessments; findings are not suppressed.

The most direct upload concern is
[CVE-2026-37555](https://security-tracker.debian.org/tracker/CVE-2026-37555),
an integer overflow in the IMA ADPCM WAV path of libsndfile. The vendor tracker
still marks the stable package vulnerable and links the
[upstream issue and merged fix](https://github.com/libsndfile/libsndfile/pull/1123).
Previously, native format inspection occurred before the WAV/FLAC admission
decision. Merely rejecting an unwanted format after parsing is insufficient.

The API now parses WAV using Python's integer-PCM reader, checks duration/rate/
channels, verifies complete frame bytes, and rewrites a canonical PCM WAV before
any native decoder receives it. This rejects compressed WAV, including the
affected ADPCM codec, and removes ambiguous/trailing chunks. Other containers
are rejected before native inspection; FLAC is explicitly admitted. Tests use a
benign ADPCM format tag and assert that native inspection is never called; they
also cover truncated data, duplicate chunks and valid PCM/FLAC. No exploit
payload is used or published. IEEE floating-point WAV is now outside the API
contract; convert it to integer PCM or FLAC before upload.

This is an API path mitigation, **not an upstream library patch or a general
memory-safety proof**. SoundFile wheels can bundle their own libsndfile; inspecting
only the OS package is insufficient. FFmpeg/PyAV and FLAC parsing also need review.
The final rebuilt images require another scan and real-model integration run.

The application NetworkPolicy now limits inbound model-service traffic to
Traefik and the configured Prometheus namespace, and outbound traffic to
cluster DNS. Models are staged before startup; model pods need no public model
download or paid API access. Loopback sidecar communication remains within the
pod. This must be exercised with the actual k3s policy implementation. Kubernetes
NetworkPolicy has node/connection-tracking limitations; it is not complete host
isolation. See the [official policy documentation](https://kubernetes.io/docs/concepts/services-networking/network-policies/).

No exception approval, security sign-off, license clearance or zero-vulnerability
claim is implied by these mitigations. Keep dated raw scans and explicit decisions
for the exact final image hashes.
